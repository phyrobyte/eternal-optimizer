# 永遠 ─ 因果最適化ラボ

[English](README.en.md) · `pip install eternal-optimizer` · MIT

**測れるものを任せてください。仕組みを教えなくても、良くする方法を自分で見つけます。**

Lunaform の因果AI「永遠（ACI）」を、ブラックボックス最適化エンジンにしたものです。
Optuna や Ax と同じ ask / tell 方式で使えます。違いは、統計モデルを当てはめる前に
**介入する**ことです。

## しくみ

1. **介入** ─ 現在の最良点のまわりで、変数を1つずつ動かす。最良点も測り直してノイズを知る。
2. **必要性の判定** ─ 動かしてもノイズ以上に結果が変わらない変数は「原因ではない」として固定する。
3. **ルール学習** ─ 残った変数の範囲を区間に分け、各区間（と区間の組み合わせ）が上位 γ に入る確率を
   減衰つきのベータ事後分布で数える。
4. **探索の門** ─ 変数ごとに、確信度 z が高いほど探索を減らす：ρ = min(ε, 1/(1+z²))、ε = 0.15 + 0.5·C(t)。
   組み合わせルールの z が大きければ、そちらが優先される。
5. **結晶化** ─ はっきり良い区間が見つかったら、その変数の範囲をそこへ絞り込む。
6. **再検査** ─ 固定した変数も、ときどき検査し直す。

## ベンチマーク（予算200試行・20シード・ランダム探索との比較）

| 問題 | ノイズ | 永遠の差（中央値） | ランダムの差 | 勝ち | 無関係な変数を正しく固定 |
|---|---|---|---|---|---|
| ラーメンの味 | 0% | 0.13 | 2.80 | 20/20 | 20/20 |
| ラーメンの味 | 2% | 0.62 | 2.97 | 19/20 | 20/20 |
| ブラニン＋ダミー6次元 | 0% | 0.016 | 0.227 | 17/20 | 20/20 |
| ブラニン＋ダミー6次元 | 2% | 0.31 | 0.34 | 13/20 | 20/20 |
| ハルトマン6 | 0% | 0.15 | 1.00 | 20/20 | ─ |
| ハルトマン6 | 2% | 0.15 | 1.00 | 20/20 | ─ |
| ローゼンブロック4 | 0% | 2.26 | 16.1 | 20/20 | ─ |
| ローゼンブロック4 | 2% | 13.4 | 24.3 | 16/20 | ─ |

際どい判定は、新しい介入で再現したときだけ「原因」と認めます（再検査）。

**弱点**：ノイズがあり、最適値付近の改善幅がノイズより小さい問題（ノイズありのブラニン）では、
ランダム探索とほぼ互角です。ノイズに埋もれるほど弱い原因（ノイズありのラーメンの「チャーシューの厚さ」）は、
固定されることがあります（ときどきの再検査で復活します）。

## Optuna・Ax との比較（同じ問題・同じノイズ・同じ採点）

**1回きりの最適化（予算100試行、シード10・Ax のみ5）**：最終順位の平均（1が最良、4手法中）。
詳細は [compare/REPORT.md](compare/REPORT.md) と [compare/compare.png](compare/compare.png)。

| 永遠 (ACI) | Optuna (TPE) | Ax (BoTorch) | ランダム |
|---|---|---|---|
| 2.60 | 2.42 | **1.25** | 3.73 |
| 0.02 秒/回 | 0.32 秒/回 | 218 秒/回 | 0.02 秒/回 |

正直に：ゼロから1回だけ解くなら Ax が全8シナリオで勝ちます。永遠は Optuna とほぼ互角で、Ax の約1万倍速く動きます。

**関連する問題の連続（ラーメン店8軒・各60試行・シード5、6軒目は曜日が効く罠）**：
前の店の経験を使える条件で比較（Optuna・Ax には前の店の全試行を履歴として渡す）。
2〜8軒目の最終順位の平均（6手法中）：

| ノイズ | 永遠・毎回ゼロから | **永遠・記憶あり** | Optuna | Optuna・履歴あり | Ax・履歴あり | ランダム |
|---|---|---|---|---|---|---|
| 0% | 4.66 | **2.20** | 3.11 | 3.14 | 2.14 | 5.74 |
| 2% | 4.71 | 2.74 | 2.71 | 3.11 | 2.06 | 5.66 |

- 記憶ありの永遠は、毎回ゼロからの永遠に 70 回中 67 回勝ちます。
- 罠の店（6軒目）では、履歴を渡された Optuna が前の店に引きずられて差 11.5（ゼロからだと 0.76）。
  永遠は記憶を「提案」として扱い介入で確かめ直すので差 0.45 で、全手法で最良でした。

再現：`.venv-compare/bin/python compare/run_compare.py 100 10 8 5`、`compare/report.py`、`compare/run_transfer.py 60 8 5 8`。

## ビルドと実行

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
./build/eternal            # アプリ
./build/eternal_tests      # テスト
./build/eternal_bench 20 200
```

GLFW 3.4、Dear ImGui 1.91.5、ImPlot 0.16 は CMake が固定バージョンで取得します。
日本語フォントは macOS のヒラギノ角ゴシックを使います。
設定パネルの「言語」で日本語と英語を切り替えられます（`--lang en` で英語起動）。

## MCP 接続（AI から操作する）

`build/eternal_mcp` は MCP サーバーです。Claude などの AI が、ツールで永遠を操作できます。

| ツール | 役割 |
|---|---|
| `create_study` | パラメータの名前と範囲を渡して研究を作る |
| `ask` | 次に試すパラメータを受け取る（種類：初期探索・介入・活用・探索・局所探索） |
| `tell` | 測った値を返す |
| `status` | 最良値、原因と判定した変数、無関係として固定した変数、ルール、出来事 |
| `list_problems` / `benchmark` | 内蔵問題でランダム探索と比べる |

Claude Code では、このリポジトリの `.mcp.json` が自動で読み込まれます。

## デモ：AI が本物のコードを速くする

`showcase/ai_tunes_matmul.py` は MCP クライアントとして永遠を操り、512×512 の行列積
（`build/eternal_matmul`）をこの機械で実測しながら速くします。つまみは tile・order・unroll と、
何もしない color・label。仕組みは教えません。

| シード | 永遠の最良 | ランダムの最良 | 永遠の判定 |
|---|---|---|---|
| 7 | 8.52 ms | 8.44 ms | 原因 = tile, order ／ 固定 = unroll, color, label |
| 8 | 8.73 ms | 8.83 ms | 同じ |
| 9 | 9.40 ms | 9.08 ms | 同じ |

教科書どおりの設定（tile=64, ijk）は 67.7 ms。永遠の最良は約 **7.8 倍速**です。
3つのシードすべてで、同じ2つの原因を見つけ、何もしない2つと、速いループ順では使われない unroll を
固定しました。ただし速さではランダム探索と互角です。この問題は1つのつまみ（ループ順）が支配的で、
偶然でも当たりやすいからです。ここで永遠が上回るのは、**何が効くのかを説明できる**点です。

```bash
python showcase/ai_tunes_matmul.py 60    # 要：pip install "mcp[cli]"
```

## 自分の問題で使う

```cpp
#include "aci_opt.hpp"

aci::Optimizer opt({{"温度", 150, 250}, {"圧力", 1, 5}, {"時間", 10, 60}}, /*seed=*/1);
for (int i = 0; i < 200; ++i) {
    auto x = opt.ask();
    double y = measure(x);   // 小さいほど良い値（最大化したいときは符号を反転）
    opt.tell(y);
}
```
